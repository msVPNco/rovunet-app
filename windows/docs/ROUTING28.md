# Local maintenance — 0.1.4-preview.1

Mahsa/public-source import now admits usable new rows without letting unsupported future protocols block the entire list. Partial results are explicitly labelled and add-only: no old profile is overwritten/deleted, no manual ID is taken over, and the last complete-refresh timestamp is not advanced. Save failure rolls back. Completely valid refreshes still replace only the matching subscription atomically. Download/decryption/empty validation failure retains previous data; canonical Mahsa routing, consent, hidden URLs and the no-ads rule remain. Future protocol execution still requires an implemented handler; unknown rows are reported rather than guessed.

The current downloaded Mahsa sample has10 distinct links:8 now parse, while2 Hysteria2 links request insecure TLS and remain rejected. The third prior rejection was VLESS flow=xtls-rprx-vision-udp443; the pinned Xray source and actual engine accept it. The parser and editor now preserve that exact flow under the existing raw/TLS-or-REALITY rules. TLS/SSH verification has not been weakened.

Collection path selection now persists manual (default), failure replacement, or smart. Smart uses fresh measurements of the same HTTPS target and switches only for latency at most half the current value. Failure replacement holds a healthy path and requires an actual core/connection failure or two failed health checks. At most one candidate in the same collection is checked every45seconds; a healthy smart switch has a2minute cooldown. Unapproved SSH/Slipstream identities, including chain layers, are not probed for auto-selection. Stop/sleep/closing, manual changes, changed routes/targets, recovered health or removed profiles invalidate pending decisions. A failed real smart reconnect attempts the formerly healthy original once, subject to unchanged identity/profile and no user cancellation. This is proxy-path failover, not device-wide leak protection.

Group test deadlines are protocol-aware (direct18s; SSH/Naive25s; DNS40s; Slipstream65s; Tor90s), including startup. Manual HTTPS verification has a25second whole-round cap; alternative targets share that deadline. Stability stops at the first failed attempt and reports the actual completed count. Manual connection remains independent of tests. Slow startup may produce an inconclusive quick test even when manual connect works.

Focused native-WPF policy/import/UI regressions and a real probe-only Agent/pinned-core loopback fixture cover whole-round timeout, cancellation and pipe/tunnel survival. They do not certify arbitrary remote peers, host TUN/SCM/boot, physical touch or mixed-monitor DPI. Public0.1.3 tags/assets and the owner installation are preserved. All prior ACT03/native gates remain open. HTML skin alternatives are design proposals only; do not integrate them before owner approval.
